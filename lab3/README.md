# Лабораторна робота №3 — Мережний рівень OSI, статична та динамічна IP-адресація (DHCP)

**Варіант 2** (остання пара цифр % 3 = 2): не вказати діапазон IP-адрес у `dhcpd.conf` і описати дефект у вигляді defect report.

## Оточення
- Ubuntu 22.04.5 LTS у VirtualBox, користувач `diana_siukalo@ubuntu-kpi`
- **PC1** — сама VM: `isc-dhcp-server` і маршрутизатор, `br-lab` `192.168.100.1/24`
- **PC2** — DHCP-клієнт, **PC3** — `10.20.0.2/24`, **PC4** — другий DHCP-сервер (мережеві простори імен Linux)

## Запуск
```bash
sudo bash lab3.sh
```
Скрипт створює стенд, виконує всі кроки, пише журнал у `~/lab3_out` і наприкінці прибирає стенд.

## Що зроблено
1. Статичне налаштування IP-адреси
2. DHCP-сервер, обмін DISCOVER–OFFER–REQUEST–ACK у Wireshark, `dhcpd.leases`, звільнення адреси
3. `ping`, `traceroute`, таблиці маршрутизації, troubleshooting
4. **Варіант 2:** конфігурація без `range` → сервер `active`, але адрес не видає (`no free leases`)
5. **Додатково:** конфлікт двох DHCP-серверів
6. Визначення DNS-сервера у Wireshark (`dns.sh`) і передача його клієнтам через `option domain-name-servers`

## Результати тестування
| ID | Перевірка | Результат |
|---|---|---|
| DHCP-TC-01 | Отримання адреси від DHCP-сервера | PASS |
| DHCP-TC-02 | Конфігурація без `range` (варіант 2) | FAIL → DHCP-DR-01 |
| DHCP-TC-03 | Два DHCP-сервери в одному сегменті | FAIL → DHCP-DR-02 |

Обидва дефекти описано у звіті, виправлено та перевірено повторно.
